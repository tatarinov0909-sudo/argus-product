# Виртуальные склады — схема (одобрена владельцем 02.10.2026)

Составлено 02.10.2026 по ответам владельца на вопросы 1–13. Код не начат —
сначала одобрение всей схемы.

## Что это

Виртуальный склад — часть товара продавца на живом складе фулфилмента,
отложенная под своё назначение. Физически товар лежит в тех же ячейках
(если не включено «хранить отдельно»), меняется только учёт.

Пример: продавец привёз 1 000 резинок — 500 на «Озон», 300 на «WB»,
200 на «ООО БББ».

## Решения владельца (вопросы 1–13)

1. Делим по площадкам (Озон, Яндекс Маркет), юрлицам продавца, своим складам
   продавца; брак — в общем списке складов. Склады WB (Краснодар, ЮГ Зелёный
   и т.п.) **не** делим.
2. Юрлица — просто склады с названием («ООО БББ», «ИП Иванов»). Ключ WB у
   продавца один, как сейчас. Аргус — для любого фулфилмента (клиенты
   Аргуса — фулфилментеры).
3. Склад указывают при привозе и при поставке на WB; поставка собирается
   только с одного склада.
4. У каждого продавца есть «Основной склад»; весь нынешний товар — на нём.
5. На склад относится количество штук: один товар может быть на нескольких
   складах.
6. Продавец видит свои склады и при привозе выбирает склад по строкам.
7. По умолчанию товар разных складов лежит в одних ячейках; для склада можно
   включить «хранить отдельно».
8. Переносить между складами могут руководитель и менеджер — сразу.
   Продавец — только заявкой в Аргусе: складу уведомление «очень важно»,
   руководитель выполняет, продавцу уведомление «сделано».
9. Подтверждение переноса — кнопкой; QR — позже, с модулем QR.
10. У склада — название и площадка: WB, Озон, Яндекс Маркет или «иное».
11. «Иное» — вне трёх площадок (напрямую, другой сайт). Поставка на WB — только
    с «Основного» и складов WB; товар склада «иное» уезжает обычной отгрузкой.
12. Акты — на кабинет продавца, как сейчас, не на юрлицо склада.
13. Недостачу при пересчёте распределяет по складам руководитель при
    подтверждении (подсказка: с «Основного», если его нет в ячейке — с самого
    большого склада); продавцу — уведомление. Излишек — на «Основной».

## Что я предлагаю там, где вопросов не было (нужно одобрение)

- **Где заводят склады:** кабинет владельца → «Продавцы и площадки» → окно
  продавца → «Склады»: название, площадка, «хранить отдельно». Переименовать —
  можно всегда. Убрать склад — только пустой. «Основной» не убирается и не
  переименовывается.
- **«Основной» — остаток.** Отдельно Аргус хранит количество только на
  складах, которые завели. «Основной» — всё остальное: так у склада с учётом
  в 1С (1С не знает о складах Аргуса) «Всего» по товару остаётся числом из 1С,
  а «Основной» = «Всего» − остальные склады. Ничего переносить при запуске не
  нужно.
- **Привоз:** продавец выбирает склад по строке; не выбрал — «Основной».
  Приход из 1С и заведённый складом вручную — на «Основной», руководитель
  может поменять до приёмки. Грузчик принимает как обычно.
- **Поставка на WB:** менеджер выбирает склад (только «Основной» и склады WB);
  если такой склад один — ставится сам. Грузчику подсказываются только
  ячейки, где есть товар этого склада; больше, чем числится на складе, взять
  нельзя. Отгрузка из 1С — с «Основного», руководитель может поменять.
- **Отгрузка со склада «иное»:** заводит фулфилментер, указывает склад,
  собирается так же.
- **Наборы:** компоненты набора берутся со склада поставки.
- **Возвраты:** годное возвращается на склад, с которого товар уезжал;
  возврат, заведённый вручную, — на «Основной», руководитель может поменять.
- **Брак:** «Склад брака» показывается в общем списке складов продавца. Брак
  помнит, с какого склада пришёл; «перепаковать» и «уценка» возвращают товар
  на тот же склад.
- **Что видит продавец:** в «Товарах» у каждого товара раскладка по складам
  и выбор одного склада. Числа по складу: «На складе», «В сборке» (поставки с
  этого склада), «Доступно». «Заказано» (заказы WB, ещё не в поставке) склада
  не имеет — показывается общим числом, как сейчас: склад определится, когда
  менеджер соберёт поставку. «Заявка на перенос» — в карточке товара.
- **Что видит фулфилментер:** «Остатки продавцов» → продавец → выбор склада и
  раскладка у каждого товара; «Перенести» в строке товара; заявки продавцов на
  перенос — в журнале «ждёт решения» с пометкой «очень важно».
- **Грузчик:** складов не видит. Исключение — склады «хранить отдельно»: у
  ячейки подписано, чей товар, приёмка подсказывает ячейки этого склада,
  перенос с/на такой склад — задание «переложить».
- **Загрузка начальных остатков из файла:** необязательный столбец «Склад»;
  пусто — «Основной».
- **Чат Кладовщика:** остатки продавца — с раскладкой по складам.
- **Журнал:** создание и изменение складов, переносы, заявки — категория
  «Склад и ячейки».

## Права склада у продавца (вопрос 14, владелец 02.10)

В кабинете продавца — «Права склада», одна галочка (владелец 02.10, уточнение):
«Запретить складу решать без меня спорные ситуации с количеством». По
умолчанию она выключена: склад решает сам, а продавцу приходит заметное
уведомление «Склад сделал так-то. Обратите внимание: склад решил это сам…».
Галочка стоит — каждая такая ситуация ждёт решения продавца.

Продавец НЕ влияет на сборку поставок: составлять поставки, убирать заказ из
поставки, принимать и отгружать склад может всегда. Спорные ситуации
(одобрены владельцем 02.10):

1. Складу поставки не хватает товара, а на другом складе продавца он есть —
   «Взять с другого склада продавца» в карточке поставки (это перенос).
2. Недостача при пересчёте ячейки — с какого склада списать.
3. Лишнее при пересчёте — на какой склад записать.
4. Расхождение при приёмке, когда товар заявлен на разные склады — какой
   склад получил меньше (больше).
5. Брак с полки, где лежит товар разных складов — с какого склада брак.
6. Перенос между складами по решению склада; сюда же — смена склада у
   строки привоза продавца.

Как работает с галочкой: учёт сразу записывается по правилу склада (полки
должны быть правдой), продавцу — «Склад ждёт вашего решения»: он
соглашается или делит по-своему, и разница переносится между его складами
(переносы ПЕР-… с пометкой «Решение продавца»). Перенос по решению склада
ждёт «Согласен» продавца, смену склада у строки его привоза склад сделать
не может.

Владелец 02.10: «Приступай к работе» — схема одобрена.

## Этап 3 — решения владельца (02.10, вечер, вопросы 1–11)

1. «Хранить отдельно» — галочка у склада продавца (вариант А) плюс, по
   желанию, закреплённая зона — свои ячейки (вариант Б). Товар такого склада
   никогда не лежит в одной ячейке с товаром других складов продавца;
   грузчику подсказываются отдельные ячейки, на ячейке подпись «склад Озон».
   В закреплённую зону ничего другого класть нельзя.
2. Включили галочку, а товар уже лежит вместе — Аргус спрашивает склад:
   создать задания грузчику на разделение или разделять только новый товар.
3. Перенос на склад «хранить отдельно» (или с него) — задание грузчику
   «переложить»; каждая переложенная штука сразу переходит на новый склад,
   непереложенное числится за старым.
4. Зона заполнена — грузчик кладёт в свободную ячейку рядом (без товара
   других складов), руководителю уведомление, куда положили.
5. «Зона заполнена» для Аргуса — нет ни одной пустой ячейки в зоне
   (вместимость ячейки знает только грузчик). Руководителя предупреждают
   заранее: когда продавец оформил привоз на этот склад и ещё раз, когда
   машина приехала, — пока зону не подготовят.
6. «Хранить отдельно» и зону включает только склад (руководитель,
   менеджер); продавец видит пометку «хранится отдельно».
7. Начальные остатки из файла — выбор «по умолчанию склад …» плюс столбец
   «Склад» в файле, если есть.
8. Возврат — по умолчанию на склад, с которого уехал заказ; склад может
   поменять при приёмке (продавцу «обратите внимание»; галочка продавца —
   решает он). Возврат без понятного заказа — на «Основной».
9. Кладовщик — отвечает по складам продавца и напоминает (переносы и
   решения ждут, зоны заполнены, задания на разделение); напоминания
   отключаются в настройках.
10. Заказ из 1С — склад выбирает менеджер в карточке заказа до сборки
    (по умолчанию «Основной»); по данным 1С автоматически — позже.
11. Брак склада «хранить отдельно» — вторая галочка «и брак тоже отдельно»,
    решает склад.

## Этапы работы

1. ✅ Сервер (02.10.2026): склады, привоз и сборка по складу, перенос,
   заявки, права, уведомления продавцу, брак с памятью склада, недостача при
   пересчёте (с «Основного», потом с самого большого склада).
2. ✅ Экраны (02.10.2026):
   - кабинет владельца: «Склады продавца» в окне продавца (завести, изменить,
     убрать пустой); «Остатки продавцов» — выбор склада, раскладка по
     складам у товара, «Перенести», заявки продавца «Выполнить / Отказать»,
     Excel по выбранному складу; склад в «Составить поставку» (на WB —
     «Основной» и склады WB); склад у строк прихода до приёмки; склад
     поставки в списке поставок;
   - кабинет продавца: «Ваш склад» в «Товарах», столбец «По складам», числа
     по складу; карточка товара — раскладка и «Попросить склад перенести»;
     просьбы склада «Согласен / Отказать», свои заявки, уведомления от склада
     с «Понятно»; «Права склада» в настройках; склад у строки привоза
     (столбец «Склад» в файле или выбор у строки); склад у строки в карточке
     прихода; «Остатки для WB» — только «Основной» и склады WB;
   - грузчик: склад поставки на карточке и в шапке сборки, склад продавца у
     строки листа отбора, «Брак» при сборке и наборы — со склада поставки;
     склад поставки на распечатке листа.
3. «Хранить отдельно» (подписи ячеек, подсказки приёмки, задания грузчику
   «переложить»), ручная раскладка недостачи и право продавца «решать по
   недостаче», столбец «Склад» в загрузке начальных остатков, склад в
   возвратах, Кладовщик по складам, смена склада у заказа 1С.

## Не входит (отложено)

QR-сканирование при переносе; склады WB по городам (решено не делить);
заказы Озона и Яндекс Маркета (интеграций пока нет — склады этих площадок
только хранят товар и уезжают отгрузкой).
