# Выпуск приложения грузчика 0.1.0

## Состав

Android-пакет `online.argus.worker`, версия `0.1.0`, код версии `1`, Android 7.0+
с обновлённым Android System WebView. Старый WebView получает экран с инструкцией
по обновлению. Рабочий API — `https://api.argus-ai.online`.

Страница установки: `https://argus-ai.online/worker-app.html`.
APK: `https://argus-ai.online/downloads/argus-worker-0.1.0.apk`.
До отметки о публикации ниже эти адреса не считаются проверенными.

Используются существующие экраны грузчика: приёмка, размещение, сборка,
бумажные листы, возвраты, брак, перемещения и пересчёт. Добавлены QR ячеек,
печать этикеток, постоянные идентификаторы действий, очередь подтверждений,
восстановление ввода и Android-события пауз. Обычный сайт и Safari на iPhone
сохраняют прежние условия работы. Публичный `loader.html` при выпуске не заменяется.

Без связи можно сохранить один шаг уже начатой приёмки или размещения с QR.
Следующий складской шаг ждёт сверки с сервером. Начало новой работы и остальные
операции требуют связи. Конфликт явно показывается и не считается успехом.
Отказ сервера разрешается только после физической сверки; неопределённый результат
снова отправляется с тем же идентификатором. Выход из Android-аккаунта сохраняет
паузу и ждёт подтверждения очереди. Восстановление входа тем же ключом доступно
отдельно при истечении авторизации.

Экран погас: через 15 секунд записывается пауза. Переход в другое приложение:
пауза с момента ухода. Краткая блокировка и запрос разрешения камеры не ставят
паузу. При отсутствии сети событие доставляется позже с исходным временем;
нельзя обещать немедленное уведомление руководителя без связи. Принудительное
завершение процесса ОС до получения события не обеспечивает точный момент ухода.
После остановки приложения системой передача сохранённых действий продолжается
при следующем открытии с доступной сетью.

Android 16+ ограничивает обычную сеть для фонового UID, даже если CPU ещё работает.
Для завершения паузы используется системный `shortService`: запуск при уходе
из видимой работы, уведомление о сохранении, максимум 90 секунд, остановка
после попытки передачи очереди, возврата или таймаута. Сервис не перезапускается
сам и не запрашивает исключение из энергосбережения. Основание:
[Android foreground shortService](https://developer.android.com/develop/background-work/services/fgs/service-types#short-service).
Успех через ADB loopback недостаточен для проверки этой гарантии: loopback
исключён из фоновой сетевой блокировки Android.

  `e85f72a3a6d98dbeab83ba78e1e7d9b106d97c8a` в `tatarinov0909-sudo/argus-api`.
- Для APK: `mobile/build-release.ps1`. Для стенда: `mobile/build-android.ps1`.
- SHA256 сертификата подписи:
  `3981f1a257a744accf587beabaa2f2d880427a4ed674bc0406d31daf37091e6f`.
- Ключ находится вне Git: `%USERPROFILE%/.codex/private/argus-worker-signing/`.
  Пароль — DPAPI текущего пользователя Windows. Переносимый резервный комплект
  пока не подготовлен; сохранить возможность подписи до замены компьютера.

Обновления должны иметь тот же сертификат и больший `versionCode`.
Опубликованные APK с номером версии в имени не перезаписывать.

## Фактически проверено

- API: 20 интеграционных проверок новых команд, 80 проверок регрессий;
  96 миграций на пустой локальной БД. Изоляция складов/исполнителей, потеря ответа,
  повтор и конкурентная отправка, QR другого склада, конфликты остатков,
  порядок пауз и физическое время завершающей приёмки.
- Client: 21 runtime/bridge проверка в `npm test`: сохранение ID, очередь FIFO,
  восстановление после перезапуска/401, отказ хранилища, два окна, переход ключей,
  повторные выходы без продолжения, ранние события запуска и одновременные
  выход из аккаунта и переход в другое приложение, нативный признак активной
  работы, ожидание отправки складского шага перед подтверждением паузы и
  сохранение блокировки при неподтверждённом возобновлении, включая бумажный лист.
- Браузерный стенд: вход, начало приёмки, QR и четыре частичных размещения через
  настоящий локальный API. Экраны на 375, 390, 768, 1440 CSS px; loading, empty,
  error, success и сохранённые действия; без случайного горизонтального скролла.
- QR-этикетки: 375, 390, 768, 1023, 1024, 1440 CSS px, декодирование QR,
  отказ одного запроса блокирует неполную печать.
- Страница скачивания и входная ссылка: 375, 390, 659, 660, 661, 768, 1440 CSS px,
  раскрытие инструкций, доступность кнопок, отсутствие ошибок JavaScript.
- `node tools/stamp-assets.js --check` — PASS; прежние общие ресурсы не изменены.

Физический ТСД, аппаратный сканер, физическая печать и Safari на iPhone здесь
не проверялись. Все 31 сценарий вручную заново на физическом складе не проходились.
Перед массовой установкой нужна приёмка на используемых моделях ТСД: ограничения
энергосбережения и встроенные сканеры различаются.

## Публикация

Статус: подготовка. Подписанный APK и рабочие адреса ещё не подтверждены.

Для API подготовлен отдельный пакет из 12 файлов и единственной миграции
`1754406200000_worker-commands`. Overlay `src/app.js` сохраняет существующий
production-маршрут `/landing-preview`, отсутствующий в исходном Git HEAD.
Предварительная проверка на рабочем сервере подтвердила точные baseline-хеши,
95 исходных миграций, изоляцию RLS, целевой процесс PM2 и health.
Перед заменой создаются проверяемые закрытые бэкапы исходников и БД; при ошибке
восстанавливаются файлы, добавленная схема с историей команд не удаляется.

Сайт публикуется по точному списку через FTPS с проверкой сертификата, бэкапами,
атомарным переименованием и сверкой SHA256 по HTTPS. Сначала APK и метаданные,
затем страница установки и ссылки в `login.html`/`index.html`.
Интеграции, настройки и данные 1С/Wildberries не меняются и не используются
для проверки; бизнес-проверки выполняются только на изолированном стенде.
