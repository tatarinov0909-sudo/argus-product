# Промт: описание сайта «Аргус» в его нынешнем виде

Ниже — полное описание того, что уже существует. Использовать как исходный промт: чтобы воссоздать сайт с нуля, передать другому исполнителю или как контекст перед доработкой.

---

## 0. Что за продукт

SaaS по подписке для владельцев fulfillment-центров — складов, которые обслуживают продавцов Wildberries и Ozon (российский рынок). Идея: команда ИИ-агентов вместо найма складских менеджеров.

Главный аргумент продукта: расхождение по количеству ловится **в момент приёмки**, а не через месяц на инвентаризации.

Три агента:
- **Оркестратор** — единая точка входа, сам ничего не решает, раздаёт задачи;
- **Кладовщик** — приёмка по штрихкоду, размещение по ячейкам, сверка с 1С;
- **Аналитик** — заполненность, оборачиваемость, отчёты, прогноз переполнения.

Четыре роли с жёстко разделённым доступом: владелец продукта, владелец склада (платящий клиент), работник склада, продавец-маркетплейсовец (клиент склада).

Символ бренда — глаз Аргуса: две открытые дуги и сплошной зрачок.

---

## 1. Состав сайта

Сайт — это набор статических HTML-файлов, лежащих в одной папке, без сборки и без фреймворков. Каждая страница открывается двойным кликом. Переходы между страницами — обычные `<a href>` и `onclick`.

| Файл | Что это | Кто заходит |
|---|---|---|
| `landing.html` | Продающий лендинг, витрина | все, вход в воронку |
| `index.html` | Точка входа: выбор роли, вход и регистрация | все |
| `cabinet_main.html` + `cabinet_main.js` | Кабинет владельца склада | платящий клиент |
| `loader.html` | Мобильный экран работника склада | сотрудник склада |
| `client_access.html` | Акты приёмки для продавца | клиент склада |
| `fonts.css` + папка `fonts/` | Самохостящиеся Inter и IBM Plex Mono | — |

Важная особенность: **лендинг и продукт сделаны в двух разных палитрах**. Лендинг — тёмно-синий с фиолетовым акцентом, продукт — тёмно-серый с бирюзовым. Это не ошибка, а текущее состояние: продукт планируется подтянуть под лендинг отдельной задачей.

Фронтенд ходит в реальный бэкенд: `const API_BASE = 'https://api.argus-ai.online'`, эндпоинты вида `/api/auth/staff/login`, `/api/auth/owner/login`, `/api/auth/owner/register`, `/api/auth/seller/login`. Сайт живёт на `argus-ai.online`.

## 2. Лендинг `landing.html`

Одна длинная страница, шесть экранов. Один файл, всё внутри — CSS, JS, SVG. Единственная внешняя зависимость: Three.js с CDN (`three@0.160.0`).

### Дизайн-система лендинга

Палитра (CSS-переменные в `:root`):

```
--midnight:#05060f            почти чёрный canvas, фон всей страницы
--steel-plate:#2f343e         поверхность
--fog-veil:#9da7ba            приглушённый текст
--moon-mist:#c7d3ea           основной текст
--frost-glow:#d1e4fa          светлые точки, частицы
--ice-highlight:#d8ecf8       блики
--pure-white:#ffffff
--void-violet:#663af3         акцент, зрачок, кнопки
--void-violet-bright:#8564ff  акцент ярче, переполненные ячейки
--blueprint-blue:#b6d9fc      контуры, обводки, hairline-графика
--gridline-blue:#3f4959       линии сетки
--glass-edge / --glass-edge-strong / --luminous-fill / --frost-wash — полупрозрачные слои стекла
```

Тени — многослойные «стеклянные»: внутренний блик сверху, внутреннее свечение, hairline-обводка 1px, внешнее свечение, глубокая тень вниз.

Шрифты: **Space Grotesk** — заголовки, **Inter** — текст, **JetBrains Mono** — eyebrow-метки, цифры, статусы.

Радиусы: карточка 16px, бейдж 6px, поле ввода 6px, кнопка 999px (пилюля).

Ритм: расстояние между секциями `clamp(96px, 11vw, 156px)`, между карточками 24px, максимальная ширина контента 1200px. Easing по умолчанию `cubic-bezier(0.16, 1, 0.3, 1)`.

### Сквозной фон

Через всю страницу, а не только в первом экране: почти чёрный `#05060f`, поверх — едва заметная сетка тонких линий и поток мелких светящихся частиц, медленно текущих снизу вверх и местами вспыхивающих. Частицы — визуальное продолжение рассыпавшегося глаза из героя, а не декоративный шум.

### Шапка

Липкая, полупрозрачная. Слева логотип-глаз (SVG: две дуги `#b6d9fc`, зрачок `#663af3`) и слово «АРГУС». По центру навигация якорями: «Как это работает», «Возможности», «Тарифы», «Заявка». Справа кнопка-контур «Войти» → `index.html`.

### Экран 1. Hero — Глаз Аргуса

Слева блок текста: заголовок «Аргус» крупно (Space Grotesk), подзаголовок «Команда ИИ-агентов принимает товар, размещает по ячейкам и сверяется с 1С в моменте приёмки», фиолетовая кнопка «Начать бесплатно» → `index.html`.

Справа — огромный глаз, занимает большую часть экрана, смотрит сверху вниз. Он **собран из тысяч мелких светящихся частиц** (Three.js `Points` + собственный шейдер, аддитивное смешивание), а не нарисован сплошной поверхностью. Две механики:

1. **Зрачок следит за курсором** — плавно, с задержкой, не резко.
2. **При скролле глаз рассыпается** — частицы разлетаются от нижнего края и уходят вниз, растворяясь в фоновом потоке. Форма не уменьшается, а распадается.

Под глазом — контурный силуэт склада: ряды ангаров и грузовик, тонкой линией 1.5px.

Внизу экрана — подсказка на скролл.

### Экран 2. Схема «Люди — Ядро — Агенты»

Идёт сразу после героя, пока внимание горячее. Заголовок «Люди говорят — агенты делают».

Три колонки:
- **Слева, «Склад»** — люди с их репликами: Кладовщик «принял 34 из 40», Руководитель «сколько места свободно?», Закупщик «пора закупать?».
- **Центр** — тот же глаз, уменьшенный. При наведении на человека или агента зрачок доворачивается в его сторону.
- **Справа, «Агенты»** — результаты: Кладовщик «расхождение −6 шт, ячейка A-14», Оптимизатор ячеек «предложена ячейка 1.3.4», Аналитик «сектор B заполнен на 91%».

Связи — тонкие светящиеся SVG-линии от человека к глазу и от глаза к агенту, ломаные, с общим стволом. По линии пробегает импульс **в момент события, не постоянно**, чтобы не рябило. На узких экранах схема перестраивается вертикально: люди сверху, глаз посередине, агенты снизу.

### Экран 3. Задачи и цели

Заголовок «Меньше ручной работы — меньше ошибок». Сетка из четырёх карточек без заливки, только hairline-рамка 1px:

1. **Человеческий фактор при приёмке** — сверка каждой позиции со штрихкодом и 1С в моменте.
2. **Автоматическое распределение по ячейкам** — агент предлагает свободную ячейку под габариты и оборачиваемость.
3. **Скорость сборки заказа** — точный адрес ячейки, сборщик не ищет вслепую.
4. **Точный учёт остатков** — каждое движение фиксируется и сверяется с 1С.

Внутри каждой карточки — маленький спарклайн и строка статуса с точкой-индикатором 6px: «0 пропущенных расхождений за 30 дней», «≈40 секунд на решение», «+18% к скорости сборки», «99.6% совпадение с 1С». Все цифры условные, помечены комментариями в коде.

### Экран 4. Карта склада

Окно с macOS-хромом: три точки, заголовок «argus — Склад №1», справа статус «на связи» с пульсирующей точкой.

Внутри — карта склада: три ряда, в каждом двенадцать ячеек. Заполненность показана полосой заливки, которая растёт по проценту; ячейки выше ~80% меняют цвет на яркий фиолетовый, пустые нарисованы контуром. Сбоку панель «Инциденты»: «Ячейка 1.4.2 — расхождение 3 шт», «Ячейка 2.1.5 — заполнена на 96%», «Ряд 3 — свободно 12 мест».

Должно выглядеть как реальный работающий интерфейс, а не абстракция.

### Экран 5. Цена

Заголовок «Один тариф на весь склад», подзаголовок «Платите за склад, а не за штат кладовщиков». Три тарифа (цифры — заглушки):

1. **Старт**, 15 000 ₽/мес — 1 склад, до 3 сотрудников, базовые агенты (Оркестратор, Кладовщик), журнал и приёмка.
2. **Рабочий**, 39 000 ₽/мес — 1 склад, до 15 сотрудников, все агенты включая Аналитика, интеграция с 1С. Бейдж «Популярный выбор».
3. **Сеть**, по запросу — несколько складов, сотрудники без ограничений, все агенты и 1С, приоритетная поддержка.

Средний тариф выделен светлой карточкой на тёмном фоне — **единственное место на странице со светлой поверхностью**. Под тарифами строка: «Не нашли свой вариант — рассчитаем под ваш склад».

### Экран 6. Заявка

Заголовок «Готовы убрать человеческий фактор со склада?». Форма: имя, телефон, название склада, кнопка «Оставить заявку». Форма **ничего никуда не отправляет** — показывает галочку и сообщение «Заявка принята, свяжемся с вами».

Подвал: «© Аргус, 2026 · ИИ-команда для fulfillment-складов».

### Технические требования лендинга

- Всё появление блоков — по скроллу, через `IntersectionObserver`.
- Если WebGL недоступен, устройство слабое или экран уже 820px — вместо 3D-глаза показывается статичная SVG-картинка того же глаза. Страница не ломается.
- `prefers-reduced-motion` отключает частицы и анимации.
- На мобильных поток частиц глушится, схема связей перестраивается вертикально.
- Обрабатывается потеря WebGL-контекста.
- Лендинг открывают с телефона у ворот склада на плохом интернете. **Вес и плавность важнее эффектности.**
- Все тексты и цифры — осмысленные заглушки, не Lorem ipsum. Места под реальные данные помечены комментариями.

## 3. Продукт: четыре страницы кабинетов

Общая палитра продукта (отличается от лендинга):

```
--bg:#15171A        --panel:#1D2023      --panel-2:#25282C     --line:#32363B
--accent:#5FAFA6    бирюзовый, Оркестратор
--terracotta:#D98E6E терракота, Кладовщик
--an:#B7A65E        охра, Аналитик
--text:#E8E6E1      --muted:#8D9096
```

Шрифты: Inter + IBM Plex Mono, самохостящиеся (не Google Fonts — чтобы не тянуть большой внешний ресурс на плохом интернете).

Адресация ячеек: `ряд.стеллаж.ярус` → `1.3.4`. Объединённые ячейки показываются диапазоном `1.3–5.2`. Полоса заполнения ячейки ведёт себя как индикатор заряда: растёт с процентом, цвет уходит от бирюзового к терракоте по мере заполнения.

### `index.html` — вход

Экран «Какой у вас кабинет? Одна система. Три роли.» Три карточки:
- **Работник склада** — вход по имени и ключу от руководителя;
- **Руководитель склада** — вход по почте и паролю, есть переключение на регистрацию (имя, название склада);
- **Продавец** — вход по имени и ключу от склада.

После успешного входа — экран подтверждения и переход в соответствующий кабинет. Все три формы бьются в реальное API.

### `cabinet_main.html` — кабинет руководителя

Боковое меню и пять разделов:
1. **Чат** — переписка с агентами, единая точка входа через Оркестратора;
2. **Журнал действий** — лента событий с бейджем непрочитанного. Цвета статусов: красный — ждёт подтверждения владельца, зелёный — подтверждено, жёлтый — применено автоматически;
3. **Склад и ячейки** — конструктор склада: ряды, стеллажи, ярусы, объединение ячеек прямоугольным блоком по обеим осям, карта заполненности, настройки склада в одном модальном окне;
4. **Сотрудники** — выдача ключей доступа;
5. **Подключение 1С**.

Пункт «Тариф» в меню есть, но пока пустой.

### `loader.html` — экран работника склада

Мобильный, вертикальный. Приёмка по шагам: сканирование штрихкода, ввод количества, выбор ячейки, экран завершения задачи. Имя работника передаётся параметром `?name=`.

### `client_access.html` — кабинет продавца

Продавец видит **только свой** товар: акты приёмки, таблица итогов с накопительным остатком и дельтой по месяцам.

## 4. Чего в продукте пока нет

Подроли работников (грузчик и старший смены — сейчас у всех одна роль), настройка «кто выбирает ячейку», раздел тарифа, обработка возвратов, отчёт по рабочему времени сотрудников, нормальная группировка журнала по дням, адаптив кабинетов под мобильные, пагинация журнала на сотнях записей, справочник габаритов (он блокирует трёх неразработанных агентов — Укладчика, Менеджера и Логиста).
