## 1. Что это за проект

**Argus** — SaaS для владельцев fulfillment-центров (складов): команда ИИ-агентов
принимает товар, размещает по ячейкам, сверяется с 1С и показывает расхождения

опечаток из переписки: «трейдеры/трайдеры» = тетраэдры, «схватки» = стеллажи,
«буры» = фуры, «прощение» = вращение.

## 4. `landing.html` — архитектура

Один самодостаточный файл. Порядок содержимого:

1. `<style>` — токены дизайна + CSS
2. разметка: `<main>` → `<section id="hero">`, внутри него `<canvas id="heroCanvas">`,
   заголовок `#heroTitleWrap`, статичный фолбэк `#heroFallback`, и **панель склада**
   `<div class="wh-panel" id="whPanel">` с `<canvas id="whCanvas">`
3. классические `<script>` GSAP + ScrollTrigger (cdnjs)
4. `<script type="importmap">` → three@0.160.0 и `three/addons/` с jsdelivr (**минифицированные сборки**)
5. крошечный classic-скрипт: `window.__argusHeroFallback()` + таймаут 1.8 с
6. **`<script type="module">` №1 — сцена глаза**
7. **`<script type="module">` №2 — сцена склада**

> Секция в разметке **одна** (`#hero`). «Экран со складом» — это не отдельная секция,
> а панель внизу того же запиненного экрана. Секций 3+ пока не существует.

### Почему две сцены, а не одна

Владелец хочет видеть глаз и склад **одновременно**: глаз сверху смотрит на склад снизу.
Двумя непрозрачными полноэкранными канвасами это не собрать, а прозрачным сделать
канвас склада **невозможно** (см. раздел 5, «граблю №2»). Решение: склад — панель в
нижних 43% того же экрана. Работает только потому, что **обе сцены чистятся одним и
тем же цветом фона**, поэтому границы двух канвасов не видно.

Сцены намеренно независимы: свои renderer/scene/camera/composer/кадровый цикл,
отдельные ES-модули. Единственная связь — **одно число в одну сторону**:
`window.__argusHeroProgress` (пишет глаз, читает склад) и `window.__argusBgClear`
(цвет фона, тоже из сцены глаза).

### Сценарий прокрутки

`ScrollTrigger` на `#hero`: `pin:true`, `end:'+=420%'`, `scrub:0.06`.

| прогресс | что происходит |
|---|---|
| 0 | заголовок «Argus» + закрытый глаз |
| 0.05 → 0.14 | глаз открывается |
| 0.14 → 0.21 | интро-саккада взгляда |
| 0.13 → 0.26 | заголовок **уезжает вверх** (не гаснет — именно уезжает, translateY) |
| 0.15 → 0.36 | склад выезжает снизу; камера глаза уводит его в верх кадра |
| 0.20 → 1.0 | живая фаза: моргание, взгляд, реакция на курсор |
| 0.36 → 1.0 | устойчивый финальный кадр (≈2/3 прокрутки) |

**Глаз больше не закрывается и не рассыпается** — эти фазы вырезаны по прямому
указанию владельца. `endPhase()` оставлена возвращающей 0, ветка разлёта в
рендер-цикле просто никогда не берётся.

### Сцена глаза — группы частиц

Геометрия `TetrahedronGeometry(1,0)`, материал `MeshBasicMaterial({wireframe:true})` —
**без освещения намеренно**: все грани одного тэт одного цвета, это требование владельца.

| группа | что | размер (база) |
|---|---|---|
| 0 | веко (контур) | `rand(0.62,0.95)` × `LID_SIZE_MUL 0.7` |
| 1 | склера (фон между веком и радужкой) | `rand(0.3,0.5)` |
| 2 | кольцо радужки | `rand(0.68,0.98)` |
| 3 | спицы | `rand(0.42,0.7)` |
| 4 | кольцо зрачка | `rand(0.32,0.46)` |
| 5 | блик | **выключен** (`GLINT_ENABLED = false`) |

Общие множители: `EYE_SIZE_MUL = 0.216`, `INNER_SIZE_MUL = 0.55` (группы 1–4),
`LID_SIZE_MUL = 0.7`. `EYE_COUNT` 8000 на десктопе (это бюджет попыток Poisson-disk,
не точное число).

**Цвет:** центр — монохромный `EYE_WHITE = 0xb8d6f4` (точная середина градиента
заголовка `.hero-title`). Веко и кольцо зрачка — непрерывный градиент по контуру
`LID_STOPS = [0x1f4f9e, 0x4fb0e0, 0x2a6fbe, 0x3d93d2, 0x1f4f9e]`, палитра **замкнута**
(последний стоп = первый), иначе на стыке t=1/t=0 виден скачок.

Вращение: `SPIN_SPEED = 1.0` рад/с, у каждой частицы своя фаза (`spinPhase`) и
скорость (`spinSpeedVar` 0.85–1.15) — **не убирать рассинхронизацию**, см. раздел 5.

### Сцена склада — текущие параметры

```
BANDS 2      полосы стеллажей       COLS 15      стеллажей на сторону
BLOCK 4      стеллажей в блоке      BLOCK_GAP 0.9
AISLE 2.2    полуширина прохода     RW 1.7   RGAP 1.25   BD 18.0   CA 2.7   RH 2.4
DOCKS 7      фур на сторону         DOCK_LEN 4.6  DOCK_W 2.4  DOCK_H 1.7  DOCK_PITCH 4.3
наклон плоскости  mesh.rotation.x = -15°        FILL 0.99
```

Каждый стеллаж — **замкнутый** прямоугольный контур на 3 уровнях (обе длинные стороны
**и оба торца**) + стойки. Товар — отдельные паллеты по ячейкам с просветами, а не
равномерная заливка. Доки — полые П-образные контуры (закрыт только дальний торец) + кабина.

Камера склада **подбирает угол обзора сама** под фактическое соотношение панели
(`fitCamera` в `layout()`) — не хардкодить fov под конкретное окно, см. раздел 5.

### Фон страницы

Ведётся прокруткой через `clearColor` **обеих** сцен (через `body` нельзя — канвасы
непрозрачны). Стопы: `#05070d → #0a0f1c → #132444 → #1e3459 → #2c4570`.
Сейчас задействованы первые три (секций 3+ нет). `BG_CLEAR` — **откалиброванные**
входные значения, см. раздел 5.

## 5. Дорого доставшиеся уроки (читать обязательно)

Каждый из этих пунктов стоил нескольких раундов правок вслепую.

**1. Правило размер ↔ количество.** Размер и количество частиц в группе меняются
**только вместе и в обратную сторону**. Увеличил размер — пропорционально снизь
количество, и наоборот. Нарушение этого правила дало и «ёжик» на веке, и кашу в центре.
Многие параметры размера (`EYE_SIZE_MUL`, `INNER_SIZE_MUL`, `LID_SIZE_MUL`) **входят
в расчёт минимальной дистанции Poisson-disk**, поэтому меняются оба эффекта сразу.

**2. Прозрачный canvas невозможен.** `EffectComposer` + `OutputPass` ставят alpha=1
по всему кадру — проверено чтением пикселей, 100% пикселей непрозрачны. Любая идея
«пусть фон страницы просвечивает под сценой» отпадает сразу.

**3. Тонмаппинг красит и фон, а формула ACES врёт.** `OutputPass` прогоняет весь кадр,
включая `clearColor`. **Аналитическая модель ACES дала ошибку втрое**: по ней вход
`#050912` должен быть почти чёрным, а реальный замер пикселей в браузере дал
`rgb(18,33,55)`. `BG_CLEAR` откалиброван по этому замеру (коэффициенты 3.60/3.67/3.06
по каналам), **не по формуле**. Если трогаете фон — калибруйте замером.

**4. Poisson-disk держит дистанцию только внутри одного вызова.** Веко строится
двумя вызовами (верхняя и нижняя дуга), поэтому в уголках, где дуги сходятся,
частицы разных половин могут лежать друг на друге. **Это известно и НЕ надо чинить
без прямой просьбы** — текущий вид владельцем одобрен.

**5. Контур должен замыкаться.** Стеллажи читались «полосами точек», пока у них не
было торцов: рейки шли только вдоль длины, коробка не замыкалась, и с любого ракурса
это были две параллельные пунктирные линии.

**6. Не хардкодить размер окна.** Несколько раундов подряд камера склада считалась под
1119×910, а у владельца окно ~1911 в ширину. Панель тогда имеет соотношение ~4.9
вместо 2.86, и склад занимал вдвое меньше ширины. Отсюда бесконечное «склад слишком
маленький». Теперь `fitCamera` считает угол от фактического аспекта.

**7. Синхронное вращение «съедает» форму.** Когда все частицы крутились с одной фазой
и скоростью, они периодически разом вставали ребром к камере и форма пропадала.
Лечится рассинхронизацией по фазе/скорости — **не возвращать общий spin**.

**8. Переход должен мельчать.** У Dala (референс владельца) на переходе частицы резко
уменьшаются и тускнеют — рассыпавшееся состояние читается пылью. Полноразмерные
частицы в переходе выглядят как «развалившийся объект» (владелец: «страшно»).
Реализовано через множители, равные нулю на обоих концах перехода, — крайние кадры
не затрагиваются по построению.

**9. Запрет на «лишний уровень».** Владелец отклонил добавление ещё одного множителя
яркости поверх существующей цепочки. Объём и затемнение делать **правкой цвета**,
а не новым слоем затенения.

**10. Палитра.** Долгое время действовал жёсткий запрет на бирюзовый `#5FAFA6`
(это цвет продукта) и требование холодной сине-фиолетово-белой гаммы. **Владелец
позже сам попросил синий/бирюзовый на веке и цвет в зрачке** — текущее состояние
это его прямое указание, не «починить» обратно по старому правилу.

**11. Модуль ловит свои ошибки и молча уходит в статичный SVG.** Один раз так уехал в
прод сломанный склад: `node --check` проходил, а сцена падала с `ReferenceError`.
Признак — вместо склада ровные векторные прямоугольники. Отсюда `check_scenes.mjs`.

## 6. Проверка перед деплоем

```bash
node check_scenes.mjs
```

Прогоняет **оба** module-блока `landing.html` в Node с заглушками THREE и DOM.
Падает (exit 1), если сцена бросает исключение **или** молча уходит в фолбэк — то,
чего `node --check` не видит. Проверено, что ловит реальный баг: при возврате поломки
даёт exit 1, после исправления — exit 0.

Дополнительно, если правится геометрия/камера: посчитать проекцию углов поля в NDC
в Node и убедиться, что ничего не обрезано (`|ndc.x| ≤ 1`, `|ndc.y| ≤ 1`). Примеров
таких расчётов много в истории коммитов.

## 7. Важное ограничение окружения

**Окно предпросмотра в моей среде почти всё время не отрисовывает кадры**
(«the Browser pane is not displayed»), а вместе с этим замораживается
`requestAnimationFrame`. Следствия:

- **Скриншот сделать нельзя** большую часть времени.
- **FPS измерить нельзя**: получал «1 fps» и на странице **без** склада тоже —
  это троттлинг неактивного окна, а не сцена. Не оптимизировать по таким числам.
- Почти все геометрические решения принимались **расчётом проекции на бумаге**,
  а не просмотром. Это ловит обрезы и промахи по кадрированию, но **не может**
  оценить плотность, фактуру и «похоже ли на референс».

**Что помогло:** владелец прислал видеозапись референса (Dala). Кадры удалось
вытащить так:

```bash
pip install imageio-ffmpeg
python -c "import imageio_ffmpeg;print(imageio_ffmpeg.get_ffmpeg_exe())"
# дальше обычный ffmpeg: -vf "fps=2,scale=..." и tile= для контактного листа
```

Это единственный раз за много раундов, когда удалось **увидеть** референс. Приём стоит
повторять.

## 8. Про «сделай 1в1 как на скриншоте»

Владелец несколько раз просил попиксельное совпадение склада с изображением,
сгенерированным Gemini. **Это недостижимо и об этом ему сказано прямо**: тот
референс — нарисованная картинка с художественными бликами и попиксельным свечением
без всякой геометрии, а у нас живая 3D-сцена, которая вращается, мигает и по которой
ездит фура. Сходятся: количество, пропорции, зазоры, полосы, ракурс, палитра.
Не сойдётся: характер частиц и свечения.

Что работает лучше всего: просить **конкретные отличия** («стеллажи вдвое длиннее»,
«между полосами больше чёрного», «тусклее»), а не общее «сделай как на скрине».
По конкретике попадание с первого раза, по общему впечатлению — хождение кругами.

триаж возвратов, ответ владельцу в чате). Клиент должен видеть лимиты в операциях/SKU,
никогда в токенах.
