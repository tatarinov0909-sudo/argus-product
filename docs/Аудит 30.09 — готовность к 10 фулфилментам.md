# Аудит 30.09.2026 — можно ли дать Аргус 10 фулфилментам без доработок под каждого

Проверку делал отдельный агент, только чтением кода, 30.09.2026 после выкладки
складов WB. Пути: `api/` — `argus-api`, `front/` — `argus-product`.
Проверено дополнительно вручную: Б1, Б3, Н10 подтверждены; рабочий сервер
подключается к базе ролью `argus_app` — изоляция по складам действует.

## Итог

Завтра — нет. Данные разных ФФ не смешиваются (изоляция в базе на всех
таблицах, кэши разделены по складу). Но подключение нового ФФ ломается в
первый день, потому что система собрана под то, как работает «Восход»:
- у продавцов ФФ без 1С (или с другой 1С) нет «Всего товара» и «Доступно»;
- ФФ с 1С сам 1С не подключит: нет кнопки выпуска ключа, модуль только под
  УТ 10.3 и коды товаров «PB…»;
- после регистрации показывается ненастоящий «ключ склада»;
- продавец, который возит в несколько ФФ, — новому ФФ падают все его заказы,
  пока менеджер не расставит склады WB.
При 10 ФФ следующим сломается фоновый обмен с WB: идёт по складам по очереди
и держит транзакцию в базе, пока ждёт WB, — кнопки менеджеров подвисают.

## Масштаб 10 ФФ × 20 продавцов (оценка по коду)

~3 запроса к WB на продавца за проход → ~600 подряд → проход 5–7 минут при
ответе WB за 0,5 с (интервал 5 минут превращается в «проход за проходом»), до
~100 минут при таймаутах. Транзакция на ФФ — 20–60 с, при сбоях WB — до
10 минут. Лимиты WB не превышаются. ~3,6 млн строк заказов в год — база
выдержит, раньше упрутся списки без постраничности.

## Черновик анкеты ФФ (6 вопросов, всё изменяемо в «Настройках склада»)

1. **Учёт остатков: в 1С или только в Аргусе?** 1С — «Всего» из 1С, ключ и
   модуль выдаются сразу, конфигурацию модуль определяет сам; только Аргус —
   «Всего» по ячейкам (нужна Б1). Смена — со сверкой; уход с 1С — только когда
   остатки загружены в ячейки.
2. **Храните по ячейкам?** Нет — одна общая зона «Склад», адреса не
   спрашиваются. Смена в обе стороны без потерь.
3. **Кто оформляет поставку FBS в кабинете WB: вы или продавец?** Вы — у
   нового продавца предлагается запись в WB (с отметкой «продавец согласен»);
   продавец — Аргус только читает. По каждому продавцу, меняется для новых.
4. **Часовой пояс** — подставлен по браузеру, подтвердить.
5. **Брак: решает продавец или склад по правилу?**
6. **С чем работаете: WB FBS / WB FBO / Ozon / Яндекс** — честно показать, что
   покрыто.

Определять самому: часовой пояс (по браузеру), название/ИНН продавца (из WB),
склады продавца, пункты приёмки, КГТ (из WB), какие пункты ваши (подсказка по
складам продавцов + «как вас называют продавцы»), работает ли продавец с
другими ФФ, настройки 1С (кнопка модуля), связь товаров WB по штрихкоду,
валюта (из заказа WB), юрлицо склада для актов (при первом акте).

## Минимум до 10 ФФ

1. Убрать ненастоящий ключ (Б3).
2. Кнопка ключа 1С, файл модуля, верная инструкция, префикс «PB» — в настройку (Б2).
3. «Всего» по ячейкам для ФФ без 1С (Б1).
4. Не брать заказы неотмеченных складов у продавцов с несколькими ФФ (Б4).
5. WB — вне транзакций в обмене (Н1), общий кэш пунктов сдачи (Н2).
6. «Настройки склада» с анкетой и восстановление пароля (Н6).
7. Убрать «Слим Тим» и неверный текст про карточки (Н10).
