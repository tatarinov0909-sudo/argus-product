# Хендофф 05.10 — починка проверки 05.10

Независимая проверка 05.10.2026 нашла 7 ошибок в добавленном 04.10. На каждую
есть падающий тест в `argus-api/test/attack-0510/`, отчёт — в `REPORT.md` там
же. Владелец: «чини всё до конца». Все 7 тестов проходят.

## Что изменилось

1. **Н6 — имя работника выполнялось как код.** Кнопка «Сделать менеджером»
   передаёт только номер работника, имя берётся из загруженного списка. Для
   строк внутри `onclick` есть помощник `jsArg` (`cabinet_main.js`): сначала
   экранирует для JavaScript, потом для HTML. Через него же идёт артикул в
   «Взять с другого склада продавца».
2. **Н1 — счёт после смены пояса склада.**
   - Счёт хранит точные границы по времени: `covers_from`/`covers_to`,
     миграция `1754405200000`.
   - Следующий счёт начинается ровно там, где закончился соседний, — в обе
     стороны смены пояса. Работа не попадает в два счёта и не выпадает из
     обоих.
   - День работы в счёте не выходит за его период.
   - У старых счетов границ нет: для них — даты в нынешнем поясе, как раньше
     (счета неизменяемы).
3. **Н5 — Excel в «Добавить товары».** Размер листа считается по самим
   ячейкам, а не по служебной пометке файла. Тест проверки собирал файл,
   который на деле содержал 2 товара, а не 4: SheetJS при записи отбрасывает
   ячейки за пределами пометки. Тест поправлен — теперь в файле 4 товара, а
   занижена только пометка. На старом коде он падает в обоих случаях, на
   новом проходит.
4. **Н2 — Excel виртуального склада узнаёт товар, как приход из Excel:**
   артикул без учёта регистра, артикул продавца и штрихкод WB. Общий каталог —
   `catalogIndex` в `src/sellers/inbound.js`. Неоднозначный ключ не угадывается.
5. **Н4 — «Ждут решения» на главной:**
   - заявка клиента на перенос считается один раз;
   - вместо «расхождений» — «вопросов в журнале»;
   - «заказов WB не сопоставлены» считает только заказы WB.
6. **Н7 — Excel расчётов у руководителя:** цены и суммы записываются числами.
7. **Н3 — неверная единица хранения в прайсе** даёт понятный отказ 400 вместо
   «внутренней ошибки».

## Замечания проверки без теста

Починены:
- Номер счёта теперь порядковый у склада: СЧ-1, СЧ-2 и так далее. Раньше
  номер брался из случайного кода и мог совпасть у двух счетов. У счетов до
  05.10 номер прежний.
- В «Работы и даты» у счёта (у руководителя и у клиента) появились цена и сумма
  каждой работы: количество × ставка строки.
- Номер операции оплаты держится, пока оплата не записана. Раньше перерисовка
  формы давала новый номер, и потерянный ответ мог записать оплату дважды.
- Клиенту больше не уходит имя сотрудника склада, менявшего его прайс.

Свой тест на это — `argus-api/test/billing-bounds-e2e.js`: сдвиг пояса на
запад, номера по порядку, прайс у клиента.

Не менялось:
- **Возврат на складе без ячеек.** Годный возврат кладётся только в ячейку, но
  и приход нельзя закончить, не разложив товар по ячейкам. Склад без ячеек
  сейчас в Аргусе не работает целиком. Это вопрос проверки универсальности
  (`argus-api/test/attack-universal-0510/PROGRESS.md`), а не возвратов.
- **Последний счёт клиента в архиве** не выставить, пока клиента не вернуть из
  архива. Это решение о том, как работать с архивом; записано в «Отложено».
- **`crypto.randomUUID`** есть только на https. Сайт работает по https, менять
  не нужно.
- **R11** (поставку нельзя разобрать во время передачи в WB) — ждёт полного
  доступа к WB.

## Вечер 05.10 — поставка WB по шагам и отгрузка вручную

Опубликовано 05.10 (API `93a3063`, сайт `93aa39c`, без миграций).

- У собранной поставки WB кнопка «Передать в доставку WB»
  (`POST /api/supplies/:id/marketplace/deliver`, теперь и в статусе `ready`).
  WB закрывает поставку и выдаёт QR до погрузки. Потом «Уехала»: второй раз
  в WB не идём (`alreadyDelivered`). Дата отгрузки на WB — плановая, если она
  ещё впереди.
- Статус поставки у владельца и продавца: «передана в доставку · QR готов» →
  «уехала, в пути» → «уехала · принято WB N из M» → «принята WB». Принятой
  считается посылка, которую опрос статусов закрыл как `fulfilled`
  (WB отсортировал и дальше).
- «Приходы и акты»: переключатель «Приход / Отгрузка вручную» и список
  «Отгрузки вручную и из 1С» (`GET /api/invoices?direction=out&source=1c`).
  Отгрузку собирает грузчик и закрывает «Отгрузили — машина уехала»; ячейки
  меняются сразу, «Всего» — когда отгрузку проведут в 1С.
- Тесты: `test/wb-handover-before-ship-e2e.js` (новый), `wb-write-e2e`,
  `shipping-e2e` (фильтр `source`). Полный прогон: e2e 82, guarded 2,
  unit 22, attacks 36 — без падений. UI: workspace, navigation-stock,
  order-workspace, virtual-warehouse-stock, warehouse-capacity прошли;
  `seller-tables` и `inventory-count` — старые падения из «Отложено».

## 06.10 — остатки с «В пути», «На WB» у склада, QR до «Уехала», приёмка WB

- «Доступно» = Всего − Заказано − В сборке − В пути. При учёте в 1С
  вычитается только едущее, которое 1С ещё числит (сверх лежащего в ячейках);
  при учёте в Аргусе «Всего» включает «В пути». `src/sellers/stock.js`.
- «На WB» против свободного — один модуль `src/sellers/wbListing.js`:
  столбец «На WB», фильтр, строка-предупреждение и совет «где снять» в
  товарах клиента у склада; отметка в «Остатках продавцов»; строка «На WB
  больше, чем свободно» на «Главной» (`/api/alerts/today` → exchange.wbOver).
  У продавца совет под числом «На WB»; файл «Остатки для WB» при нескольких
  складах WB не предлагается.
- «Уехала» у поставки WB, созданной Аргусом, — только после «Передать в
  доставку WB» (QR), если запись на WB включена; сервер отвечает 409.
- Кабинет продавца, «Поставки»: столбец «Приёмка WB» — «принято N из M»,
  «ещё в пути K», «отменено». Статус: «Уехала» → «Принята WB».
- Тесты: `test/stock-transit-wb-over-e2e.js` (8), `seller-stock-e2e`
  (+ случай «1С ещё не списала»), `tests/navigation-stock-ui.cjs` (строка
  «Главной»).
