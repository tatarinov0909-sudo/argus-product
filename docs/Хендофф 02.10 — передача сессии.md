## 1. Следующая задача: 7 находок проверки остатков (не починены)

Отчёт с примерами и местами в коде лежит в
`argus-api/test/attack-stock-0110/REPORT.md`, ход проверки — в `PROGRESS.md`
там же. На каждую находку есть тест, который падает на нынешнем коде (код

1. **Остатки продавца грузятся долго.** У продавца с 12 тыс. товаров — 130 с,
   у продавца с 300 товаров — 3,3 с. В `src/sellers/stock.js` LATERAL по

2. **Карта склада у владельца** открывается 12–27 с: для строк остатка в
   ячейке товар ищется без подходящего индекса. Тест:
   `perf-warehouse-map-e2e.js`.
3. **Учёт 1С.** Поставка уехала после последнего числа из 1С — Аргус
   перестаёт вычитать её заказы, «Доступно» завышено до следующего обмена.
   Тест: `onec-shipped-after-snapshot-e2e.js`.
4. **Галочка «наш» на складе WB** возвращает давно закрытые на WB заказы

   `wb-checkbox-brings-back-closed-orders-e2e.js`.
5. **«В пути» не уменьшается:** после отгрузки статус заказа у WB больше не
   спрашивается. Тест: `transit-never-clears-e2e.js`.
6. **«На WB» пусто**, если первые заказы товара пришли до сопоставления с WB.
   Тест: `wb-stock-lost-after-late-mapping-e2e.js`.
7. **Выгрузка остатков через API** не знает учёт «Аргус». На сайте она не
   используется. Тест: `export-ignores-argus-accounting-e2e.js`.

## 2. Решения этой сессии, которых нет в отложке

- **Правило «наш склад WB» только ставит отметку, снимает только человек.**
  Так решено после проверки 01.10. Возвращать автоснятие нельзя: заказы
  молча уходили из работы.
- **«Доступно» считается по товарам с учётом** — это не ошибка, оставлено как
  есть. На экране подписано.
- **Вход владельца несёт отпечаток пароля.** После выкладки 01.10 все
  владельцы один раз вошли заново — это ожидаемо.
- **Сравнение с 1С не считать ошибкой Аргуса.** Владелец: 1С иногда вносит
  товар позже. Проверять нужно, что Аргус правильно вычитает заказы из того
  числа, что дала 1С.

## 3. Как работать с владельцем

- Писать очень просто, один вопрос за раз.
- Спрашивать подробно: как это работает на деле, пример с его данными, что
  будет при каждом варианте и чем он плох. Короткие «вариант A / B» он не
  понимает.
- Различия фулфилментов: автоопределение → один вопрос анкеты → можно
  исправить позже. Ничего не подгонять под «Восход».
- Проверку делает агент без памяти: только ищет ошибки, на каждую пишет
  падающий тест и ничего не чинит. Чинит основная сессия, а агент сохраняет
  находки в файл сразу (лимит может кончиться посреди работы). Модель для
  проверки — Opus.
- «Делай / чини всё до конца» владелец даёт как разрешение на выкладку.
