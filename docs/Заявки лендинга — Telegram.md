# Заявки лендинга и Telegram

Заявки — данные самого Аргуса. Они доступны только явно назначенному
администратору продукта; регистрация владельца склада не даёт этого права.
Раздел: `/leads.html`, ссылка в меню аккаунта назначенного администратора.

## Подключение

1. Войти в свой существующий кабинет владельца Аргуса и открыть «Заявки с лендинга».
2. Создать отдельного бота через официального `@BotFather`, команда `/newbot`.
3. Вставить токен в защищённое поле раздела Telegram. Токен хранится
   зашифрованным, после сохранения не возвращается браузеру.
4. Открыть полученную одноразовую ссылку на бота и нажать «Старт».
5. Вернуться и нажать «Я нажал „Старт“». Приходит сообщение о подключении.

Ссылка действует 15 минут. Подключается только личный чат, подтвердивший эту
ссылку. Чужое сообщение боту не меняет получателя. Бот с уже установленным
webhook другого сервиса не переподключается автоматически.

## Доставка и работа с заявками

- Приём заявки сохраняет её в PostgreSQL независимо от Telegram.
- Фоновая доставка проверяет очередь каждые 30 секунд. Временные ошибки и
  ограничения Telegram вызывают повтор с увеличивающейся паузой.
- Старые заявки до первого подключения остаются в списке. Чтобы отправить
  старую недоставленную заявку, администратор нажимает кнопку в её строке.
- Статусы «Новая», «Связались», «Закрыта» сохраняются отдельно от доставки.
- Отключение Telegram удаляет сохранённый токен и получателя, не удаляя заявки.
- Секреты и содержимое ответа Telegram не записываются в ошибки и логи.
- Доставка — минимум один раз: при потере ответа после принятия сообщения
  Telegram возможен повтор. UUID заявки в сообщении позволяет распознать дубль.

## Сопровождение

Администраторов назначает оператор сервера по существующему owner UUID:
`scripts/lead-admin.js` в API. Права на назначение не выдаются роли приложения.
При отзыве доступа ранее выданный JWT не открывает раздел.

Ключ шифрования — существующий серверный `MARKETPLACE_KEY_SECRET`; он нужен
для восстановления настроек из копии базы. Копировать его в git или документы
нельзя. Резервное копирование сохраняет конфигурацию отдельно от открытого SQL.

Контракт Telegram проверен по официальным страницам:
[Bot API](https://core.telegram.org/bots/api) и
[Deep linking](https://core.telegram.org/bots/features#deep-linking).

Реальная доставка считается подключённой только после подтверждения личного
чата владельцем. Проверки с подставленным Telegram проверяют код, а не заменяют
этот последний шаг.
