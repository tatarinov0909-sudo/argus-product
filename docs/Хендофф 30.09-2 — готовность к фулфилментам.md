## Что сделано

1. **Анкета и «Настройки склада».** После регистрации вместо ненастоящего
   «ключа склада» — три вопроса: где учёт остатков (1С / только Аргус), кто
   оформляет поставку в кабинете WB (склад / продавец), часовой пояс (по часам
   компьютера). Всё меняется на новом экране «Настройки склада» (там же
   название, город, юрлицо, «как вас называют продавцы на WB», смена пароля).
   Пока анкета не заполнена — «!» у пункта меню. Поля — в `warehouses`
   (миграция `1754403700000_warehouse-settings.js`), API — `GET/PATCH
   /api/warehouses/me`, сверка перед сменой учёта — `GET
   /api/warehouses/me/stock-sources`.
2. **Склад без 1С.** Ответ «только в Аргусе» — «Всего товара» у продавца
   считается по ячейкам Аргуса: годное в ячейках + собранное, но не
   уехавшее (`sellers/stock.js`, `source`). Смена учёта показывает, насколько
   изменятся числа. Тест `test/seller-stock-cells-e2e.js`.
3. **Часовой пояс склада** вместо зашитой Москвы: номера поставок и приходов,
   «дата отгрузки прошла», утренняя сводка в 7:00, время в журнале, «сегодня»
   в кабинетах (`src/warehouses/time.js`).
4. **Склады WB — строгое правило.** Заказы берутся только со складов продавца,
   отмеченных вашими. Пункты приёмки Аргус добавляет сам при первом чтении
   складов (там, где у продавцов склады с вашим именем); «Слим Тим»-случай
   (единственный склад на вашем пункте без вашего имени) считается вашим.
   Пока склад ни разу не настраивался — заказы берутся как раньше (чтобы
   обновление ничего не спрятало). «Как вас называют продавцы» — доп. имена
   для правила.
5. **Подключение 1С без разработчика.** Кнопка «Выпустить ключ для 1С»,
   ссылка на модуль с инструкцией, верная инструкция (Конфигуратор), честно:
   поддерживается УТ 10.3 и коды «PB…». Файлы модуля на сайте есть (аудит
   этого не проверил — проверено).
6. **Обмен с WB.** Каждый продавец — своя короткая транзакция, по 4
   одновременно (раньше одна на весь склад). Кэш пунктов сдачи WB: одинаковые
   списки хранятся один раз.
7. **Списки.** Экран «Акты» больше не тянет все заказы WB; грузчику не
   отдаются закрытые документы старше 14 дней; `/api/supplies?limit=`.
8. **Смена пароля владельца** в «Настройках склада» (узкие функции в базе,
   миграция `1754403800000_owner-password-change.js`). Восстановление
   забытого пароля — нужен почтовый ящик (см. «Что нужно достать»).
9. **Ключ WB:** при подключении сразу читаются склады продавца и
   запоминается, чей это кабинет WB (название, ИНН) — видно в карточке.
10. Тексты: убран «Слим Тим» из «Расчётов», исправлено «карточки не
    читаются».

## Сбой 30.09 19:44–20:03 на рабочем сервере и что исправлено

Владелец нажал «Добавить все» (6 пунктов). Старая версия добавляла пункты по
одному: после первого (Краснодар) остальные 5 складов «Восхода» на миг стали
«чужими», и их заказы (4 166) ушли в отложенные, затем вернулись «как новые»
(новая запись заказа, без статуса WB). Обмен статусов за три прохода закрыл
их заново — это ~2 850 лишних записей «Обмен с WB» в журнале; у 3 067 заказов
Авезова новая запись, ссылки старых записей журнала на них потеряны.
Итог по работе: 227 заказов в работе, как и должно быть; 1 122 отложенных —
действительно склады других фулфилментов. Резервов товара не было.

Исправлено: убранный заказ хранится целиком (`invoice_row`, `item_rows`) и
возвращается тем же — номер записи, даты, статус WB; обмен сначала
возвращает/убирает, потом принимает очередь; «Добавить все» — один запрос,
один пересчёт (`PUT /api/marketplaces/wb/offices`). Тест
`test/wb-warehouses-upgrade-e2e.js`.

Не сделано без решения владельца: удалить лишние записи журнала (журнал
только дописывается, удалить можно лишь суперпользователем базы).
