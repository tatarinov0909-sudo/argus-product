# Кто что может в Аргусе

Составлено 9 сентября 2026. Четыре живых человека и один обмен. Документ —
источник правды при спорах «а можно ли ему это».

## Правило, из которого всё остальное

**Владелец умеет всё. Менеджер — то же самое минус деньги, доступы и
структура склада.**

Одна фраза вместо таблицы разрешений на каждый экран: менеджер живёт
в потоке заказов, но не раздаёт ключи, не перекраивает склад и не видит
счетов. Проверять при этом надо один короткий список, а не матрицу.

---

## Селлер — клиент фулфилмента

Ему нужно одно: знать, что с его товаром, и **не звонить владельцу**. Всё
остальное на этом экране лишнее.

**Видит**

- Остаток тремя числами рядом:
  - **на складе** — что числится по 1С после последней реализации
  - **в новых заказах** — что уже заказали, но ещё не собрали
  - **доступно к продаже** — первое минус второе
- Движения: что приехало, что уехало, что вернулось и в каком состоянии
- Акты приёмки — только свои
- Историю по конкретному товару
- Выгрузку в Excel

**Не может**

- Видеть чужой товар. Проверяется базой, а не честным словом.
- Менять что-либо на складе: он читатель, и только.
- Писать агентам. Правило владельца: агент с продавцом не разговаривает.

**Вход:** по ключу, без пароля. Ключ выдаёт и отзывает владелец, отзыв
действует в ту же секунду.

**Чего пока нет:** уведомлений «товар кончается», «приехал возврат».

## Кладовщик — человек на складе

Работает руками, смотрит в телефон. Всё, что он видит, — это **что сделать
следующим**.

**Умеет**

- Приёмка: накладная → позиция → сколько принял по факту → в какую ячейку.
  Брак отмечается отдельно и в остаток продавца не попадает.
- Лист сборки: что собрать, из каких ячеек, в порядке обхода.
- Отгрузка: снять с полки, закрыть позицию.
- Возврат: разобрать, годное на полку, битое в брак.
- Перемещение между ячейками.
- Инвентаризация: получить задание по ячейкам, ввести пересчёт.
- Сборка наборов из компонентов.

**Не может**

- Открыть чат с агентами. Жёсткое правило владельца: посреди приёмки
  работник в переписку не уходит.
- Заводить и править накладные — он исполняет, а не назначает.
- Видеть склад целиком и чужие компании.

**Вход:** по ключу, без пароля.

## Менеджер — сотрудник владельца

Тот, кто каждый день превращает заказы маркетплейсов в собранные поставки.
Новая роль: **сегодня её в системе нет вообще**, есть только владелец,
работник, продавец и обмен.

**Умеет**

- **Заказы с маркетплейсов.** Не сплошной список, а сперва: у кого
  накопилось. Партнёр — и число заказов без поставки. Фильтры по
  маркетплейсу, складу, статусу.
- **Одной кнопкой отправить заказы клиента на сборку.**
- **Собрать поставку** из отобранных заказов, получить её номер и статус.
- **Документы поставки:**
  - лист подбора для кладовщика — артикул, фото, название, штрихкод, QR;
    количество по одинаковым артикулам **суммируется**, чтобы кладовщик
    шёл за товаром один раз;
  - лента наклеек из кабинета маркетплейса, с настройкой «сколько ШК
    на единицу»; печать по позиции и по всей поставке; общий файл на
    несколько поставок с заглушкой между ними;
  - QR-код поставки;
  - пропуск водителю.
- Заводить накладные на приёмку руками, если 1С у клиента не подключена.
- Видеть карту склада, остатки, ячейки, журнал действий.
- Назначать инвентаризацию.

**Не может — то самое урезание**

| Чего лишён | Почему |
|---|---|
| Клиенты и доступ | завести клиента, выдать ключ продавца или ключ маркетплейса — решение владельца, а не оператора |
| Сотрудники | выдавать и отзывать ключи работникам |
| Структура склада | ряды, ячейки, зоны, импорт карты из 1С |
| Подключение 1С | ключ обмена — это доступ к учёту клиента |
| Тариф и деньги | счета, оплаты, стоимость хранения |
| Чат с агентами | остаётся владельцу |

**Вход:** по ключу или паролю — решить отдельно. Ключ проще, пароль
уместнее для человека, который сидит за компьютером весь день.

## Владелец фулфилмента

Всё, что умеет менеджер, **плюс шесть строк из таблицы выше**. Отдельно
стоит назвать то, что есть только у него:

- **Клиенты и доступ.** Завести клиента, выдать ключ его кабинета, привязать
  ключ маркетплейса. У ключа маркетплейса видно срок — они протухают, и
  один такой ключ у нас уже умер молча.
- **Сотрудники.** Ключи работникам и менеджерам, отзыв в одну секунду.
- **Склад.** Ряды, ячейки, зоны разгрузки, импорт карты из справочника 1С.
- **Подключение 1С.** Ключ обмена, расписание, что именно выгружается.
- **Деньги.** Тариф, счета, стоимость хранения и обработки.
- **Чат с агентами.** Кладовщик отвечает, где лежит товар и сколько его;
  Оркестратор распределяет вопрос между агентами.
- **Журнал действий целиком**, с обратным ходом: из записи в ячейку,
  из ячейки в накладную.

## Что из этого уже работает

| Роль | Готово | Нет |
|---|---|---|
| Селлер | остаток, движения, акты, Excel | три колонки вместо одной, уведомления |
| Кладовщик | приёмка, сборка, отгрузка, возврат, перемещение, инвентаризация, наборы | сканер (штрихкодов в 1С почти нет) |
| Менеджер | — | роли не существует |
| Владелец | всё, кроме денег и аналитики | тариф, аналитика |

## Порядок, в котором это делать

1. **Три колонки в кабинете продавца.** Заказы уже приезжают — 357 штук
   лежит. Считать нечего, надо показать.
2. **Роль менеджера** и экран заказов с группировкой по клиентам.
3. **Поставка как объект** и её документы.
4. Лента наклеек — упирается в API маркетплейса, не в нас.
