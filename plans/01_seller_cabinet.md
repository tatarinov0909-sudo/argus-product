# План 01 — кабинет продавца

Цель: продавец получает понятный и безопасный кабинет, который отвечает на
вопросы об остатках и движении товара без обращения к фулфилменту.

## Фаза 0. Подтвердить данные и границы

- [ ] Проверить, что каждая операция и остаток привязаны к конкретному продавцу.
- [ ] Не открывать доступ на данные общей компании-заглушки.
- [ ] Сверить фактические ответы API для остатков, заказов, движений и актов.
- [ ] Зафиксировать формулу «доступно к продаже» и источник резервов.
- [ ] Проверить наличие и качество штрихкодов для будущей выгрузки в 1С продавца.

## Фаза 1. Остаток

- [ ] Сделать стартовым экраном остаток с тремя итоговыми числами.
- [ ] Добавить таблицу товаров утверждённой структуры.
- [ ] Показать нехватку и сверку с 1С только при расхождении.
- [ ] Добавить раскрытие причин брака и переход в историю товара.
- [ ] Проверить отображение на широком экране и телефоне.

## Фаза 2. Заказы и движения

- [ ] Сгруппировать заказы по утверждённым статусам продавца.
- [ ] Показать время ожидания и счётчики групп.
- [ ] Привести «Уехало», «Вернулось» и «Приехало» к утверждённым таблицам.
- [ ] Проверить, что ссылки на документы и ячейки относятся только к продавцу.

## Фаза 3. Акты, история и выгрузки

- [ ] Доработать акты: расхождения сверху, заявленное и принятое видны сразу.
- [ ] Реализовать ленту истории товара в обратном хронологическом порядке.
- [ ] Выгружать в Excel только данные текущего экрана и фильтра.
- [ ] Сформировать первый тестовый файл остатков для импорта в 1С продавца по
  штрихкоду.

## Фаза 4. Вход и приёмка

- [ ] Добавить первый вход: ключ, имя и почта; сохранять имя и почту за ключом.
- [ ] Проверить изоляцию данных двумя тестовыми продавцами.
- [ ] Проверить все состояния: нет остатков, есть брак, нехватка, расхождение с
  1С, новые заказы, возврат и отгрузка.
- [ ] Утвердить сценарий с владельцем фулфилмента и зафиксировать результат.
