# Приложение грузчика: локальная разработка

Android-проект для Android Studio: эта папка `android`. Нажать **Open**, выбрать её и дождаться Gradle Sync. Новый пустой проект создавать не нужно.

Серверная часть находится в отдельной ветке `codex/worker-offline-api` репозитория `argus-api`; для рабочих сборок нужны её миграция и маршруты. Текущий выпуск — [0.1.1](../docs/worker-app-release-0.1.1.md); первоначальная публикация и границы офлайна описаны в [отчёте 0.1.0](../docs/worker-app-release.md). Обычный сайт остаётся доступен как запасной способ работы.

## Сборка

- Node.js и npm, Java 21, Android SDK Platform 36, Build Tools 35.0.0.
- Исходный интерфейс — существующий `../loader.html`; дополнительные возможности из `../worker` включаются только в сборке приложения.
- `npm ci` устанавливает закреплённые зависимости.
- `npm run build` собирает веб-просмотр с тестовым API `http://127.0.0.1:3110`.
- `npm run sync` собирает Android-вариант с тестовым API `http://10.0.2.2:3110` и копирует его в Android-проект.
- Из папки `android`: `./gradlew.bat :app:assembleDebug`.
- На подготовленном компьютере все шаги выполняет `./build-android.ps1`; итог копируется в `output/argus-worker-0.1.1-stand.apk`.
- APK: `android/app/build/outputs/apk/debug/app-debug.apk`. Минимальная версия Android — 7.0 (API 24).

Адрес API задаётся переменной `ARGUS_API_BASE` **до** сборки. Разрешён только адрес сервера без пути, параметров и учётных данных. `10.0.2.2` — адрес компьютера только из Android-эмулятора; для физического телефона нужен доступный ему тестовый сервер. Не вводить рабочие ключи в тестовый стенд.

Для диагностического соединения с локальным стендом доступны `adb -s emulator-5554 reverse tcp:3110 tcp:3110` и сборка `./build-android.ps1 -ApiBase http://127.0.0.1:3110`. Loopback обходит часть фоновых сетевых ограничений Android, поэтому такая проверка сама по себе **не подтверждает** отправку паузы при выключенном экране через обычную сеть. Для приёмки нужен обычный маршрут к стенду и контроль публичного HTTPS API.

В текущем окружении Java, SDK и Gradle подготовлены в локальной игнорируемой папке `../.tools`. Для консольной сборки установить `JAVA_HOME` в `.tools/jdk-21`, `ANDROID_HOME` в `.tools/android-sdk`, `GRADLE_USER_HOME` в `.tools/gradle-user-home`. Java, встроенная в установленную Android Studio, новее версии, требуемой этой сборкой: в Gradle JDK выбрать подготовленную Java 21.

Debug имеет отдельный идентификатор `online.argus.worker.debug` и допускает HTTP для локального стенда. Release использует `online.argus.worker` и рабочий API только через HTTPS. `./build-release.ps1` собирает и подписывает выпуск; существующий выходной APK не перезаписывается. Не публиковать тестовый APK как рабочую версию.

Для обновлений сохранять тот же ключ подписи и увеличивать `versionCode`/`versionName` в `android/app/build.gradle`; публиковать APK с новым именем. `sign-release.ps1` проверяет release-пакет, рабочее окружение, подпись и выравнивание. Ключ находится вне Git в `%USERPROFILE%/.codex/private/argus-worker-signing/`, пароль защищён Windows DPAPI текущего пользователя. Переносимая резервная копия этого ключа отдельно пока не подготовлена: перед заменой компьютера нужно сохранить ключ и доступ к нему безопасным способом. Не коммитить содержимое папки подписи.

## Границы первого этапа

- QR ячейки проверяется относительно склада и выбранной позиции. Ввод от сканера ТСД принимается с Enter; камера использует локальную библиотеку распознавания.
- Каждое поддержанное действие сохраняется с постоянным идентификатором до отправки. Повтор после потери ответа использует тот же идентификатор.
- Без связи сохраняется **один складской шаг** приёмки или размещения уже начатой работы; затем нужно дождаться сверки с сервером. Это ещё не непрерывная работа всего склада офлайн. Для размещения без связи необходим QR ячейки.
- Конфликт не считается успехом и не удаляется: запись показывается для разбора с руководителем. Начало новой работы и неподдержанные операции требуют связи.
- Android: погасший экран более 15 секунд вызывает паузу; уход из приложения вызывает паузу без этого ожидания. События сохраняются на устройстве и восстанавливаются после возврата. Без связи уведомление руководителя может прийти только после доставки события серверу.
- Обычный сайт и iPhone сохраняют прежние правила браузерного таймера. На iPhone используется Safari → «Поделиться» → «На экран Домой».

## Приёмка перед распространением

Проверить настоящий ТСД (модель, версия Android, сканер и режим энергосбережения), физический Android, Safari на iPhone, разрешение камеры, блокировку экрана и смену приложения, потерю связи и восстановление, все рабочие сценарии из задания. Проверить совместимость сервера, подпись APK и механизм обновления. Эмулятор и автоматические тесты не заменяют эту приёмку.

Команды UI/серверных проверок и результаты конкретного запуска фиксируются в отчёте выпуска. Тестовые учётные данные и снимки с ними не входят в исходники и APK.
